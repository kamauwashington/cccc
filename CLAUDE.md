# Claude Code Crash Course

This repository holds eight small example projects. Each one teaches a single
Claude Code feature. Each one starts broken or incomplete and ends in a state a
test can verify.

## Writing rules

These apply to every README, every code comment, every SKILL.md, every agent
prompt, and every commit message in this repository.

1. No em dashes anywhere. Use a period, a comma, or parentheses instead.
2. No "not X, but Y" sentence construction. Say the thing directly.
3. Plain language. Write "runs before the tool call" instead of "intercepts the
   invocation lifecycle". Assume the reader is skimming on a projector.
4. Short sentences. Break long ones in two.
<!-- prose-lint-ignore -->
5. No filler openers such as "It is worth noting" or "Importantly".

`scripts/lint-prose.mjs` enforces rules 1 and 5 automatically. Run
`npm run lint:prose` before you commit.

## Layout

- `examples/NN-name/` is one self contained workspace. Launch Claude Code from
  inside it, never from the repository root.
- `template/` is the canonical workspace skeleton. Copy from here so the
  workspaces do not drift.
- `scripts/` holds setup, reset, start, verify, preflight, prose lint, and
  launcher.

## Rules for working in this repository

- Never add anything to the root `.claude/` directory except `settings.json`.
  A skill or a `CLAUDE.md` placed there loads into all eight examples and ruins
  the isolation story. `scripts/verify.mjs` fails the build if you do.
- Every workspace carries a complete copy of its own settings. Settings do not
  inherit from a parent directory. The duplication is required and intended.
- `.claude/settings.local.json` is generated by `scripts/setup.mjs` and is
  gitignored. Never commit it and never hand edit it.
- `.pristine/` inside each workspace is the reset snapshot. Do not edit files
  there while working on an example. Change the live files, then refresh the
  snapshot on purpose.
